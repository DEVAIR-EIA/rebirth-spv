# ReBirth — Design Context

## Product
ReBirth is a one-click SPV factory on Solana. A user supplies a name, jurisdiction, and target raise, and within ~60 seconds the protocol mints a Token-2022 instrument, deploys an SPV state account, and returns a deploy receipt that doubles as the legal artifact. The on-chain mint *is* the membership instrument; the SPV state PDA is its registry entry.

## Design Context

### Users
Crypto-native fund managers, angels, and syndicate leads. They already understand wallets, signatures, and on-chain settlement. They are evaluating ReBirth against Carta, Sydecar, Allocations, and AngelList Rolling Funds — products that take days and thousands of dollars to spin up a vehicle. Sessions are short and goal-directed: deploy a vehicle, share the receipt with co-investors / counsel, and move on. The interface is consulted in the same context as a term sheet or subscription doc — never casually browsed.

### Brand Personality
Institutional, precise, serious. Three words: **fiduciary, instrument, executed.** The product should feel like the receipt of a settled trade and the cover page of a prospectus simultaneously. Trust is earned through restraint and technical precision, not through marketing voice. No crypto-native exuberance, no playful microcopy, no "let's go!" buttons.

### Aesthetic Direction
- **Reference points**: Stripe and Mercury — editorial typography, generous paper-white surfaces, careful spacing, color used only to mark state. The Bloomberg-Terminal influence is in the *seriousness and precision*, not in the density or amber-on-black palette.
- **Anti-references**: Phantom's marketing site, Magic Eden, generic "web3 dashboard" templates with neon gradients, glassmorphism, glow-on-hover. Also avoid the SaaS-marketing-page look (hero illustration + 3 feature cards + testimonial grid).
- **Theme**: Light by default — paper-white surfaces, ink-black type, the canonical brand surface, reads as a legal/audited document. Dark mode is a secondary affordance for power-user sessions, not a co-equal brand.
- **Imagery**: None. No illustrations, no stock photography, no decorative SVGs. The only "imagery" is data: addresses, signatures, slot numbers, jurisdictions — set as carefully as a stock certificate.

### Typography Direction
- **Display** (page titles, instrument names, receipt headers): **Spectral** (Production Type, Google Fonts). A document-grade serif designed for screen reading; carries the prospectus / annual-report register without being historical. Used at large sizes with restraint — never a wall of serif body copy.
- **Body & UI** (labels, paragraphs, buttons, navigation): **Hanken Grotesk** (Google Fonts). A refined neo-grotesk that reads as institutional without being Inter / Helvetica. Tabular numerals enabled for figures.
- **Mono** (mint addresses, signatures, slot numbers, programs IDs): **JetBrains Mono**. Used *only* for on-chain identifiers — never for body, never as a "tech aesthetic" tell. When mono appears, it means "this is a verifiable on-chain artifact."

### Color Direction (OKLCH, light theme)
Tint everything toward a cool ink hue (h ≈ 250) so neutrals stay coherent with the single accent.

- `--paper`        oklch(98.5% 0.004 250)   — page surface
- `--paper-raised` oklch(99.5% 0.003 250)   — card / form surface
- `--ink`          oklch(18% 0.013 250)     — primary text, near-black with a cool tint
- `--ink-muted`    oklch(42% 0.012 250)     — secondary text, captions
- `--ink-faint`    oklch(60% 0.010 250)     — labels, metadata
- `--rule`         oklch(91% 0.006 250)     — hairline borders, table dividers
- `--rule-strong`  oklch(82% 0.008 250)     — emphasis borders
- `--signal`       oklch(48% 0.15 250)      — single accent, used only for: primary CTA, active/success state, link underlines on hover. Never decorative.
- `--alert`        oklch(50% 0.18 25)       — error / destructive state only.

Dark mode (secondary): invert lightness (paper → near-black `oklch(14% 0.01 250)`, ink → `oklch(94% 0.005 250)`), keep the same accent hue with chroma reduced ~30 % to avoid glare.

### Spacing & Density
4pt scale, semantic tokens (`--space-2xs` through `--space-3xl`). Form fields and table rows are tighter than typical SaaS (≤ 36px row height) to communicate "trading desk", but headings get generous air above them so the hierarchy reads as a printed document, not a dense terminal. Body line-length capped at 65ch.

### Design Principles (the load-bearing rules)
1. **Document-grade restraint.** Hairline rules (1px), generous paper. No drop shadows, no rounded-card-inside-rounded-card, no pill chips with colored backgrounds. If it would look out of place in a printed prospectus, cut it.
2. **One signal color.** `--signal` is reserved for active state + the single primary CTA per page. The product is otherwise monochrome ink-on-paper. Color is a *signal*, not decoration.
3. **Mono means "on-chain truth."** Mint addresses, tx signatures, program IDs, slot numbers. Never use mono to "look technical." Reserve it so it carries meaning.
4. **No icons before headings.** No 32×32 rounded-square icon above every section title. Headings carry themselves through type and space.
5. **The receipt is the artifact.** Treat the deploy receipt page as the legal/audit object the user will screenshot, link, and forward to counsel. Layout, hierarchy, and language match the seriousness of that artifact — not a "success! 🎉" toast.

### Accessibility
WCAG AA contrast as a floor (text ≥ 4.5:1, large text ≥ 3:1, UI components ≥ 3:1). Tabular numerals on all figures. Visible focus rings using `--signal` at 2px outline + 2px offset (no `outline: none` without an equivalent replacement). `prefers-reduced-motion` respected — page-load reveals only, no looping animation. Mint addresses and signatures must remain selectable and copyable.
